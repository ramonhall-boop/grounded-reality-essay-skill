# Grounded Reality Essay

把抽象观点写成“能落到地上”的文章：先从一个具体人、具体处境、具体成本切入，再解释背后的资源约束、制度规则、激励结构、风险和时间成本，最后把故事提升为可复述的机制。

本 skill 蒸馏的是**推理框架、选材方式和文章结构**，不是某个具体作者的声音。不得冒充、署名、复刻或刻意复制特定作者的标志性措辞、口头禅、段子和个人经历。

## When to Use

使用本 skill，当用户要写：

- 社会观察、普通人处境、教育、就业、阶层、收入、创业、商业、文化变迁类文章；
- “为什么会这样”“普通人为什么很难做到 X”“一个制度/规则如何影响具体生活”类问题；
- 知乎长回答、公众号文章、博客观点文；
- 需要“故事感 + 现实感 + 机制解释”，但不想写成纯情绪或空泛鸡汤的内容。

不要用本 skill 做以下事情：

- 冒充或逐句模仿某个具体作者；
- 大段复刻来源文章、案例或标志性表达；
- 把来源人物的个人经历改头换面后当成用户自己的经历；
- 未核验就输出敏感的历史、政治、医学、法律、统计数据；
- 使用本次蒸馏中明确排除的征婚、相亲、恋爱、婚姻、怀孕类素材作为“来源思想”。

## Core Model: 六镜头现实拆解

面对一个题目，至少使用其中 3 个镜头；复杂题目使用 4–6 个。

1. **资源**：钱、时间、学历、土地、住房、人脉、工具、信息、体力，谁拥有什么，谁缺什么？
2. **制度**：规则、资格、门槛、产权、组织流程、平台机制、城市/乡村规则怎样塑造行为？
3. **激励**：每个角色为什么愿意/不愿意做？收益、损失、责任分别落在谁身上？
4. **风险**：失败一次要付出什么代价？穷人和富人的“可承受失败次数”是否不同？
5. **时间**：一件事真正需要多久？有没有“先熬三年才看见回报”的滞后？
6. **认知差**：不同阶层、地区、职业看到的是不是两个完全不同的世界？

默认假设：**很多看似道德、性格、努力的问题，先检查是不是约束条件和激励结构的问题。** 但不能把一切都简化为经济决定论。

## Workflow

### Step 1 — 把题目改写成“机制问题”

先写两行：

- 表面问题：用户原题。
- 机制问题：真正要解释的约束或结构。

例：

- 表面问题：为什么很多大学生知道要实习，却一直不投简历？
- 机制问题：当“第一次失败成本被想象得很高、行动反馈又很慢”时，人为什么会用继续准备替代真正行动？

### Step 2 — 选择一个“落地锚点”

优先顺序：

1. 用户提供的真实经历或公开可验证案例；
2. 普通生活中的典型场景；
3. 公开报道/数据；
4. 假设案例（必须明确写“假设”）。

锚点必须包含至少两个具体元素：人物、金额、时间、物件、动作、地点、流程。

不要编造“我认识一个人”“我小时候见过”这类伪第一手经历。

### Step 3 — 画出机制链

用 3–6 个节点写出：

`起点条件 → 行为选择 → 成本/风险 → 反馈 → 长期结果`

如果链条中出现“所以”“因此”但中间缺一个可解释的因果环节，补上它。

### Step 4 — 做一次成本账

至少回答其中 3 个：

- 入场成本是什么？
- 每月/每次成本是什么？
- 失败一次损失什么？
- 最慢多久能看到回报？
- 谁承担风险，谁拿收益？
- 有没有替代方案？替代方案为什么更受欢迎？

把“难”翻译成具体成本，不停留在形容词。

### Step 5 — 做一个跨域类比

可选：古今、城乡、上班/创业、租房/买房、平台/线下、学校/职场。

类比只用于**解释结构**，不是证明。类比后必须补一句：两者在哪些地方不同。

### Step 6 — 证据分层

给关键句在草稿阶段标注：

- `[F]` 可核验事实
- `[O]` 观察/经验描述
- `[I]` 推断
- `[V]` 价值判断

交稿前删掉标签，但必须检查：

- `[F]` 是否有可靠来源；
- `[I]` 是否被写成了确定事实；
- `[O]` 是否被夸大成“所有人都这样”；
- `[V]` 是否与事实混在一起。

高风险事实按照 `references/fact-checking.md` 执行。

### Step 7 — 按“故事 → 机制 → 反直觉 → 回到现实”成文

默认结构：

1. **开头结论**：1–3 段，直接给反直觉判断。
2. **具体场景**：把问题放进一个人能看见的生活画面。
3. **机制拆解**：用 2–4 个小标题展开资源/制度/激励/风险/时间。
4. **算一笔账**：用真实或明确假设的数据把抽象词变具体。
5. **类比**：让陌生机制变熟悉。
6. **反方检查**：主动写一个“但这并不意味着……”。
7. **结尾机制句**：把全文压成一句能复述的话。

### Step 8 — 去掉“模仿痕迹”

完成后检查并删除：

- 来源作者的标志性口头禅、署名习惯、固定求赞语；
- 来源文章中的独特比喻、长串排比、原始案例细节；
- 为了“像某人”而刻意加入的粗口、方言、戏谑。

保留的是：现实锚点、机制思维、成本意识、制度意识、具体化表达。

## Voice

默认语气：

- 中文口语化，但不油腻；
- 短段落，重要判断单独成段；
- 少用抽象名词堆叠，多写动作、成本和具体物件；
- 可以反问，但每 500 字不超过 2–3 次；
- 可以用幽默，但不靠羞辱某类人制造效果；
- 不默认使用粗口；
- 不卖惨，不把“普通人”神圣化，也不把“成功者”妖魔化。

## Article Modes

### A. 长观点文

- 1500–3000 中文字
- 3–5 个小标题
- 至少 1 个具体案例 + 1 个机制链 + 1 次反方检查

### B. 短观点文

- 700–1200 中文字
- 开头直接下判断
- 只保留 1 个核心机制，不贪多

### C. 自媒体长文草稿

在 A/B 基础上，额外输出：

- 3 个标题；
- 1 句封面/摘要文案；
- 3 个可切成短视频口播的观点句。

## Output Contract

除非用户另有要求，先输出：

1. **一句话核心判断**
2. **文章结构（5–8 行）**
3. **正文**
4. **事实核验清单**（只列需要核验的关键事实，不虚构来源）

如果用户说“直接给正文”，可以省略 1、2，但不能省略事实核验。

## Quality Gate

交稿前逐项检查：

- [ ] 开头 150 字内有明确判断，而不是铺垫半天。
- [ ] 至少出现一个可视化的具体场景。
- [ ] “难/卷/穷/阶层/机会”等抽象词至少被一次翻译成具体成本或机制。
- [ ] 文章至少回答一次“谁承担成本、谁得到收益”。
- [ ] 至少区分一次短期收益与长期收益。
- [ ] 类比没有被当成证据。
- [ ] 没有伪造第一手经历。
- [ ] 没有把推断写成确定事实。
- [ ] 没有复刻来源作者的独特句子或人物故事。
- [ ] 最后一段能压缩成一句“机制句”。
